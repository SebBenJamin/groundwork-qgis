# Geophysics Workbench 0.9.0: Add Data and placement

Any text table can now be added as a model, and models are placed on the real electrode
positions. **Add ERT Model…** becomes **Add Data…**, profiles can be made from the file
itself, and sections without heights are drawn as local sections you can lift with one
reference height.

## Existing projects: models move to the surveyed positions

This is a change for projects made with 0.8. Models are now placed by the same rules as new
ones. Where a profile has surveyed stations and something that links station numbers to
distances in the model file (a readings file such as the BERT `.data`, stored distances, or
a station spacing you typed), the model is **pinned to the real station positions** and
stretched evenly between them. In 0.8 it sat rigidly on the line from station 1.

Which profiles are affected: those with surveyed stations **and** a readings file, stored
distances or a typed spacing, and also those with surveyed stations and a model given as rows
or columns of cells, whose top edge gives a guessed spacing that fits the stations: such a
model is pinned by the guessed spacing. Profiles with stations that 0.8 invented, or with
only a triangulated model and no readings file, do not move.

Measured on copies of the two real demos:

| Demo | Profile | Largest shift against 0.8 |
|---|---|---|
| Erfurt | ERT02 | 0.195 m |
| Erfurt | ERT03 | 0.330 m |
| Erfurt | ERT04 | 0.621 m |
| Erfurt | ERT06 | 0.260 m |
| Erfurt | ERT07 | 0.170 m |
| Erfurt | ERT11 | 0.577 m |
| Erfurt | ERT12 | 0.542 m |
| Gülpe | Transect 3 | 0.228 m |
| Gülpe | Transects 1, 2 and 4 | 0.000 m (no readings file, no distances: they do not move) |

The Erfurt profiles and Gülpe Transect 3 are pinned by their readings files; the 0.9 Gülpe
demo ships Transect 3's measured data with it. Nothing else in an old project
changes: your interpretation, notes, boreholes and styles stay as they are. That also means
that interpretation you traced over a model in 0.8 stays where you drew it while the model
under it moves, by up to 0.6 m on the Erfurt profiles above. **Look at your interpretation on
the profiles that moved** and adjust boundaries you traced along the model.

- Stations that 0.8 invented from a spacing on a drawn line (no heights, exactly on the line,
  evenly spaced) are recognised and never used as known points. They stay stored and drawn.
- A profile whose stations have no heights and whose models carry real elevations (such as
  the pyGIMLi VTK results) now gets a ground line from the first model's top. Smooth and
  contour views fill up to it; station ticks, points, field notes, boreholes without their
  own collar height, new interpretation and the borehole viewer use it.
- A depth model on a profile without any heights is no longer an error: it is drawn as a
  local section.

## What's new

**Add Data…**

- One dialog for every file. Known formats are recognised as before; for any other text
  table you set the **delimiter**, header lines and decimal comma, and say what the columns
  are: **Position** (distance along the line, or map coordinates with their coordinate
  system), **Vertical** (**Elevation**, **Depth below surface** or **Local height**) and
  **Value** (**Resistivity** or another quantity with a unit, optionally log10).
- First guesses come from the column names and the numbers; remarks columns are marked "not
  used". The preview shows the first rows with their roles. The summary (with skipped rows),
  the fit report, the electrode note and the warnings stay in view right above **Add**, however
  far the dialog is scrolled. The last settings are offered again for a file with the same
  columns.
- **Where the Line Runs**: an existing profile, a selected line, start and end points, a
  positions file, a point layer, or the file's own coordinates. The new line is drawn on the
  map while the dialog is open. A failed import saves nothing; once the data are saved, a
  problem refreshing the view afterwards is only a warning, so pressing **Add** again cannot
  add the file twice.
- A file in map coordinates is projected onto the line. Cells past the ends of the line (a
  model's padding) are placed along the line's first and last segment extended, at their real
  distance before the start or after the end; the preview counts them.
- The entry is enabled as soon as a workbench project is open.

**Known points and the fit report**

- A surveyed position whose distance in the file is known is a known point. With two or more,
  the model sits at the real positions. The fit report names the largest shift ("5 known
  points, largest shift 1.6 m at station 16"). A shift larger than half the gap between known
  points is shown in the warning colour, followed by "Check the station spacing or the station
  numbers." **Profile Properties…** shows the same line, live, for the spacing and positions
  you are editing.
- A typed station spacing is stored; a guessed one never. A guess that does not fit is not
  used, and the profile says so: "Known points not used: the station spacing guessed from the
  model does not fit them; type the station spacing in Profile Properties".

**Electrodes you did not import**

- Derived from the readings file, a typed spacing, or guessed from a cell model. They are
  never stored: they show as the temporary map layer **electrodes (derived)** and as dashed
  ticks in the section, with a line saying which kind. Field notes by electrode number work
  on them.

**Local sections and reference height**

- A profile with no heights at all is drawn local. **Reference Height…** lifts it to real
  elevations with one height at one position; interpretation follows it, the section zooms to
  show it at its new height, and Ctrl+Z undoes it.

**New Profile… and Profile Properties…**

- **New Profile…** uses the same "Where the Line Runs" choices and **Reverse the line**. It
  has no tabs and no station spacing any more, and invents no stations.
- **Rename Profile…** becomes **Profile Properties…**: name, station spacing (with the fit
  report), **Reference Height…**, and **Set surveyed positions** with **Keep the line** or
  **Move the line to the points**. Everything is saved together or not at all. Interpretation
  and field notes drawn past the ends of the line keep their distance beyond the ends when the
  line moves.

See the guide: [Add data](../user/howto/add-data.md) and [Placement on the electrodes](../user/howto/placement.md).

## Menu names

| 0.8 | 0.9 |
|---|---|
| Add ERT Model… | **Add Data…** |
| Rename Profile… (menu and section panel) | **Profile Properties…** |

## Your files are updated once

The first time 0.9 opens a workbench file (`*_workbench.gpkg`) it adds one column to the
stations (their distance in the model file; schema 3). After that, **0.8 can no longer open
the file**. Keep a copy if you need to go back. A file that cannot be written (read-only,
open in another program) is refused with a message and left untouched.

## The electrode guess on the demo data

The guess reads the top edge of a model given as rows or columns of cells. On the small
synthetic demo models, against their real electrode files:

| Profile | Guessed | Real |
|---|---|---|
| P1 | 95 electrodes, median spacing 2.500 m | 48 electrodes, median spacing 4.997 m |
| P2 | 143 electrodes, median spacing 2.500 m | 72 electrodes, median spacing 4.997 m |

Here the cells are half an electrode spacing wide, so the guess comes out at half the real
spacing and about twice the count: it is within a factor of two, and it is only a guess.
It is marked as one and never stored. Type the spacing in **Profile Properties…** when you
know it. The demo project has a typed spacing of 5 m on P1 and P2, so it opens with the
models pinned to the stations and without the "Known points not used" note.

On sparse survey points the placement holds: thinning every demo profile to every fifth
electrode (plus the last) with a typed spacing moves the model by at most 0.18 m against
using all electrodes (Erfurt) and 0.11 m (Gülpe).

## What to try

1. Open the Erfurt demo: ERT04 now sits up to 0.6 m from where 0.8 drew it. Open a copy of the old project in 0.8 if you want to compare.
2. **Add Data…** with a text table of distance, depth and resistivity on a drawn line.
3. Add the same model with easting, northing, elevation and resistivity columns.
4. Open **Profile Properties…**, type a spacing, and look at the dashed electrode ticks and
   the map layer **electrodes (derived)**.
5. Set a **Reference Height…** on a local section and press Ctrl+Z.

## Known limits

- The section panel's own axis cannot be relabelled, so a local section shows depths there as
  negative numbers. Plates show them as positive depths.
- While a profile has no heights (a local section) there is no DEM line, no boreholes, no ties
  with other profiles and no interpretation export for it. Set a **Reference Height…** to get
  them back.
- The electrode guess is twice the electrode count on the demo row models (see "The electrode
  guess on the demo data" above); type the spacing when you know it.
- GPS tracks and other lines are used as drawn, with no smoothing.
- Readings (a, b, m, n with apparent resistivity) from free text files are not supported yet.
- A 3D model only two cells wide is not refused as "an area" and may give a zig-zag line; the
  map preview shows it before you save.
- **Add Data…** has no **Reverse the line**; **New Profile…** has.
- An older plugin (0.8) cannot open a workbench file updated by 0.9.
